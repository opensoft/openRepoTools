## 5. Follow-ups before cutover

1. **A bootstrapped triad root is "dirty" to `resume`.** `setup-openspeckit`
   writes the managed block into the tracked `AGENTS.md` and `CLAUDE.md`
   (unless `--no-repo-agent-pointers` is passed), and leaves `.specify/` and
   the agent directories untracked. It also writes three untracked files into
   the spec leg, which the root reports as ` M spec`. Any of these makes
   `resume <Name>` refuse the root and skip `make resume`. Today's per-clone
   excludes do not cover the spec-leg files.
   - This is Brett Heap's posture decision (root-guidance §8). The options
     measured here: land `openspec/README.md`, `openspec/changes/archive/.gitkeep`
     and `openspec/specs/.gitkeep` in the spec leg before cutover, through a
     spec PR and a root pin bump; run the bootstrap with
     `--no-repo-agent-pointers`, or commit its block; and carry the four root
     excludes.
   - A leg's `info/exclude` lives in its common git dir, so it applies to
     **every feature worktree** of that leg. A directory pattern there would
     hide feature work from park's `git add -A`. Use exact paths only.
   - Owners: Brett (posture); workBenches (what the bootstrap writes).
2. **The overlay does not travel with a clone.** On a fresh workstation,
   `resume <Name>` clones and bootstraps, then refuses until the person runs
   `setup-openspeckit` and runs `resume` again. Put that order in the T018
   real-half and T019 runbook. Under a temporary HOME, the shim also needs
   `WORKBENCHES_ROOT`.
3. **Feature worktrees never initialise the code leg's nested dependency.**
   Neither `create-new-feature.sh` nor `resume.sh` runs a nested
   `submodule update`. Two consequences:
   - `upstream/openRepoShape` is empty in every code feature worktree, so the
     command tests skip there and composed checks lack the dependency.
   - A parked gitlink move is **silently dropped** by a default resume on
     another workstation. The workaround measured here is
     `git submodule update --init upstream/openRepoShape` in the code worktree,
     and `resume <Name> -- --keep-staged` when the parked code WIP moves a
     gitlink.
   - Owner: workBenches (initialise nested submodules in leg worktrees, or warn
     when an un-committed WIP carries a `160000` change).
4. **New feature branches track `origin/main`,** so `status` calls a pushed
   park "unpushed to origin/main". After a resume elsewhere the branch tracks
   `origin/<branch>`, so the same feature reads differently on two machines.
   Owners: workBenches (`--no-track`, or `push -u` at park) or this repository
   (`status` reading `origin/<branch>`).
5. **A park that refuses every feature still rewrites the record's header.**
   `parked_at` and `parked_by_lane` change, with the subject "0 feature(s)".
   A third machine would then misread whose park the record holds. Owner:
   workBenches `park.sh`.
6. **Partial parks reach the person as exit 2.** `park.sh` exits 3, make prints
   `Error 3`, and `park` says "`make park` exited 2". The Makefile header says
   so, and the make line is the one to read. This repository's `park` could
   relay the code. Optional.
7. **Run OpenSpec only from the spec leg or a spec worktree.**
   - From the root or the code leg, 1.6.0 reports "No active changes found."
     and `validate --all --strict` passes vacuously with exit 0. Any CI or
     agent validation step must change into the spec leg, or use a store that
     resolves it.
   - The bench's `PATH`-first 1.2.0 fails two of five changes that 1.6.0
     passes. This predates the split, but the bench should resolve 1.6.0.
     Owner: workBenches.
8. **Select a feature with `.specify/feature.json` or `SPECIFY_FEATURE_DIRECTORY`,
   never `SPECIFY_FEATURE` alone.** The latter yields a `BRANCH` and a
   `FEATURE_DIR` that disagree.
9. **`speckit.git.validate.md` has no three-leg rule;** the installed skill
   does. Owner: workBenches, in the command doc.
10. **`status` does not report open feature worktrees,** either before any
    record exists or after a resume that `park` will next refuse (rows 50
    and 78). Consider a line for each. Owner: this repository.
11. **Wording:** `resume --dry-run` reports the estate "absent … the workspace
    was not cloned" when the workspace clone exists but has not been pulled.
